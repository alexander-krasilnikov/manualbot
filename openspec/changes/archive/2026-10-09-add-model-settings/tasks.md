## 5. Switching models (App)

- [x] 5.1 Keep the ingestion run task in `AppModel`, so it can be cancelled and awaited, in place of today's fire-and-forget `Task` (design D7). Verify with an app unit test that cancelling it during a stub ingestion leaves the job resumable and the document pending. The run loop lives in the ingestion service (`IngestionService.stop()`), because runs start from several places. Verified in Core (`ModelSwitchIngestionTests`): stopping keeps the job's progress and the document pending, and the same service runs again.
- [x] 5.2 Add `AppModel.switchModel(to:)`. It stops the answer, cancels ingestion, unloads both engines and activates the new model. For a language model it rebuilds the chat service; for an embedder it rebuilds `core`, `library`, `chat` and `source` through `build(for:)`, which runs `reindexOutdated`. If the new engine fails to load, the previous selection is restored and the error shown (design D7). Verify with app unit tests in stub mode that after an embedder switch every document is queued for re-index under the new identity, that a streaming answer is saved as stopped, and that a failing factory leaves the previous model active. A job started by another embedding model starts over in a new generation, so one generation never mixes vectors of two models (design D11). The new model is loaded at once, and the previous one is restored if that fails.
- [x] 5.3 Count the documents for the confirmation with `documentIDs(notEmbeddedBy:)` for the new identity (design D7). Verify with an app unit test on `InMemoryDocumentRepository` that the count equals the number of searchable documents. Counted by `IngestionService.outdatedDocuments(for:)`: tested in Core on `InMemoryDocumentRepository`, and in an app test on the real database.
- [x] 5.4 Gate photo import, photo questions and text-to-photo retrieval on `profile.supportsImages`, with an explanation naming the active embedder, and skip image embedding during ingestion when it is false (design D8). Verify with a Core test that a text-only profile indexes a PDF's chunks and no image vectors, and with an app unit test that the photo button's explanation names the model. A photo is now refused at import without an image model. A stored photo document keeps its old vectors while a text-only embedder is active (design D8).
