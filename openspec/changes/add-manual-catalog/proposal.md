# Proposal

## Why

A new library is empty, and finding public manuals worth importing takes time. The app is built for field technicians, so it should let them fill the library in a few taps from a curated list of real, public technical PDFs: manuals, product catalogs and whitepapers. The list also shows retrieval working on realistic documents, including photo search on the catalogs. Public links go stale, so the list needs a way to check and refresh it from time to time.

## What Changes

- Add a **Manual catalog** the user opens from the library's import menu, next to "Files". It is a bundled list of 70 curated PDFs in nine categories: Automotive, Motorcycle, Ships, Yachts, Manufacturing, Wind turbines, Field service, Military and Couchbase. Each entry has a title, publisher, kind (manual, catalog or whitepaper), size, page count and licence note.
- Browse by category, search by text, filter by kind, and import one or several entries. Each row shows its state: not imported, downloading with progress, queued, in library, or failed with a reason and retry.
- A catalog import downloads the PDF into a temporary file and hands it to the existing import path. Ingestion, OCR, the 20 MB limit, sync and re-indexing are unchanged.
- Record where a catalog document came from (catalog entry id and source URL) on its document record, so the catalog can show "In library" and the source viewer can show the origin.
- The catalog says plainly that the app is going online and from which host. Nothing else about the offline stance changes: the downloaded document stays on the device.
- Add a **maintenance script** (`scripts/`) for the people who maintain the list: `check` verifies every entry against the live web, `refresh` updates the recorded size, page count, checksum and verification date, and `rebuild` regenerates the bundled catalog from the curated source, including promoting a verified alternate when an entry has died.
- Keep the curated source (selected entries plus verified alternates, and the rejected ones with reasons) in the repo as the source of truth for the script.

## Capabilities

### New Capabilities
- `manual-catalog`: the bundled curated list, the browsing and import interface, per-entry state, download rules and failure handling.
- `manual-catalog-curation`: the maintenance script that checks, refreshes and rebuilds the curated list, and the rules an entry must meet to be selected.

### Modified Capabilities
- `document-ingestion`: the supported import sources gain the manual catalog, and an imported document records its origin when it came from there.

## Impact

- **UI:** library import menu and a new catalog sheet (`App/Library/`), a new view model and downloader port.
- **Core/Ports/Adapters:** a catalog model and loader (like `ModelManifest`), a PDF download adapter built on `URLSession` (reusing the resume and verification approach of `URLSessionModelDownloader`), and a small addition to the document record for its origin.
- **Resources:** bundled `ManualCatalog.json`, generated by the script. No PDFs are bundled.
- **Network:** HTTPS to public hosts. The Info.plist needs no transport-security exception, but the app's "everything stays on this iPad" copy and the README must say downloads happen.
- **Sync:** the origin metadata travels with the document record. The 20 MB limit already keeps every catalog entry shareable.
- **Docs:** README, `docs/using.md` and `docs/demo.md` get a short section.
- **Risks:** some hosts block non-browser clients (HTTP 403 to curl), links rot, and the content is third-party copyright. The catalog links and never mirrors.
